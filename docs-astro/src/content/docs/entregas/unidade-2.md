## Unidade 2

Durante a segunda unidade, a equipe focou no desenvolvimento detalhado do backlog, criação de user stories, design do sistema no Figma e início da implementação do MVP.

### Principais Entregas

#### Backlog do Produto

- Product Backlog completo com priorização MoSCoW
- Histórias de usuário (US-001 a US-012) com critérios de aceitação
- Definição do MVP com 10 user stories prioritárias
- Ligação completa entre Características da Solução, Requisitos Funcionais e User Stories

#### Requisitos do Sistema

- Requisitos Funcionais (RF-001 a RF-010) detalhados e categorizados
- Requisitos Não Funcionais (RNF01 a RNF12) com prioridades definidas
- Rastreabilidade completa entre requisitos e user stories

#### Design e Prototipação

- Protótipos de alta fidelidade no Figma
- Fluxos de navegação principais
- Design system básico com componentes reutilizáveis
- Validação de UX/UI com o cliente

#### Definition of Ready e Definition of Done

- Critérios de prontidão (DoR) para histórias de usuário
- Critérios de conclusão (DoD) para funcionalidades
- Processo de validação e aprovação estabelecido

#### Documentação

- Cronograma detalhado das 12 sprints
- Processo de Engenharia de Requisitos
- Comunicação e colaboração da equipe
- Lições aprendidas da Unidade 2

### Artefatos Produzidos

- Backlog do Produto priorizado
- Requisitos Funcionais e Não Funcionais
- Protótipos Figma validados
- Definition of Ready (DoR)
- Definition of Done (DoD)
- Documentação técnica atualizada
