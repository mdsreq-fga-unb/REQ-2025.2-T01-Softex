## Backlog Geral

<div class="softex-process">
> No contexto do sistema de reservas de salas e estações da Softex, o **Product Backlog** é uma lista dinâmica e priorizada de funcionalidades, melhorias e ajustes. Ele guia a equipe para entregar valor cedo a usuários-chave (colaboradores, gestores e administradores) e evolui com feedback, uso real e mudanças de processo.
</div>

## Features

| **Nome** | **Título** | **Descrição** |
|----------|------------|---------------|
| **F01** | Reservas de salas e estações | Criar, editar/cancelar e solicitar reservas (salas e estações), com prevenção de conflitos e confirmações. |
| **F02** | Visualização e mapa de ocupação | Mapa interativo em tempo real, filtros por andar/setor e estado de ocupação. |
| **F03** | Integrações externas | Sincronizar com enviar notificações/alertas via Slack. |
| **F04** | Relatórios e gestão | Relatórios de uso/ocupação, métricas e monitoramento de capacidade com alertas. |
| **F05** | Administração e permissões | Gestão de usuários, papéis/perfis e cadastro/edição de recursos (salas, estações, equipamentos). |

## Critérios de Aceitação

<div class="softex-process">
> Os critérios de aceitação definem quando uma história de usuário está completa e atende aos requisitos esperados.
</div>

### US-001 — Reservar Sala

<ul class="softex-list">
  <li>O sistema deve listar salas disponíveis por data/horário</li>
  <li>O sistema deve bloquear reservas com conflito de horário</li>
  <li>O sistema deve confirmar a reserva com sucesso</li>
</ul>

### US-002 — Editar ou Cancelar Reserva

<ul class="softex-list">
  <li>O sistema deve permitir editar data/hora/participantes até X minutos antes do início</li>
  <li>O sistema deve cancelar reserva com aviso de confirmação</li>
  <li>O sistema deve enviar notificação após alteração</li>
</ul>

### US-003 — Reservar Estação de Trabalho

<ul class="softex-list">
  <li>O sistema deve listar estações por setor/andar</li>
  <li>O sistema deve exibir capacidade e recursos disponíveis</li>
  <li>O sistema deve reservar pelo mesmo fluxo das salas</li>
</ul>

### US-004 — Visualizar Mapa Interativo

<ul class="softex-list">
  <li>O sistema deve exibir estações ocupadas em vermelho e livres em verde</li>
  <li>O sistema deve atualizar automaticamente a cada alteração</li>
  <li>O sistema deve permitir filtros por andar/setor</li>
</ul>

### US-005 — Receber Notificações no Slack

<ul class="softex-list">
  <li>O sistema deve enviar DM/alerta no Slack para criar/editar/cancelar reservas</li>
  <li>O sistema deve enviar lembrete 15 minutos antes do início da reserva</li>
  <li>O sistema deve evitar duplicidade de notificações</li>
</ul>

### US-006 — Gerar Relatórios de Uso

<ul class="softex-list">
  <li>O sistema deve gerar relatórios por período (dia/semana/mês)</li>
  <li>O sistema deve exibir taxa de ocupação e horários de pico</li>
  <li>O sistema deve permitir exportar em PDF/Excel</li>
</ul>

### US-007 — Monitorar Capacidade

<ul class="softex-list">
  <li>O sistema deve exibir painel com métricas em tempo real</li>
  <li>O sistema deve enviar alerta quando capacidade atingir ≥ X%</li>
  <li>O sistema deve permitir parametrização do limiar de alerta</li>
</ul>

### US-008 — Cadastrar e Gerenciar Usuários

<ul class="softex-list">
  <li>O sistema deve permitir CRUD (criar, ler, atualizar, deletar) de usuários</li>
  <li>O sistema deve permitir definição de papéis (usuário, gestor, admin)</li>
  <li>O sistema deve validar e-mail corporativo no cadastro</li>
</ul>

### US-009 — Cadastrar e Editar Recursos

<ul class="softex-list">
  <li>O sistema deve permitir CRUD de salas/estações/equipamentos</li>
  <li>O sistema deve permitir edição de capacidade/recursos/localização</li>
  <li>O sistema deve permitir desativar recurso temporariamente</li>
</ul>
