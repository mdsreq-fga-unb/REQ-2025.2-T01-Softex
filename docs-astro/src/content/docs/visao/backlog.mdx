## Backlog Geral

<div class="softex-process">
> No contexto do sistema de reservas de salas e estações da Softex, o **Product Backlog** é uma lista dinâmica e priorizada de funcionalidades, melhorias e ajustes. Ele guia a equipe para entregar valor cedo a usuários-chave (colaboradores, gestores e administradores) e evolui com feedback, uso real e mudanças de processo.
</div>

## Critérios de Aceitação

<div class="softex-process">
> Os critérios de aceitação definem quando uma história de usuário está completa e atende aos requisitos esperados.
</div>

### US-001 — Reservar Sala
**[↑ Voltar para US-001](#us-001)** | **Característica:** [C01 - Reservas de salas e estações](#c01) | **Requisito:** [RF-04](/REQ-2025.2-T01-Softex/visao/levantamento-parcial#rf-04--reservar-locais-de-trabalho-)

<ul class="softex-list">
  <li>O sistema deve listar salas disponíveis por data/horário</li>
  <li>O sistema deve bloquear reservas com conflito de horário</li>
  <li>O sistema deve confirmar a reserva com sucesso</li>
</ul>

### US-002 — Editar ou Cancelar Reserva
**[↑ Voltar para US-002](#us-002)** | **Característica:** [C01 - Reservas de salas e estações](#c01) | **Requisito:** [RF-05](/REQ-2025.2-T01-Softex/visao/levantamento-parcial#rf-05--editar-reservas-)

<ul class="softex-list">
  <li>O sistema deve permitir editar data/hora/participantes até X minutos antes do início</li>
  <li>O sistema deve cancelar reserva com aviso de confirmação</li>
  <li>O sistema deve enviar notificação após alteração</li>
</ul>

### US-003 — Reservar Estação de Trabalho
**[↑ Voltar para US-003](#us-003)** | **Característica:** [C01 - Reservas de salas e estações](#c01) | **Requisito:** [RF-04](/REQ-2025.2-T01-Softex/visao/levantamento-parcial#rf-04--reservar-locais-de-trabalho-)

  <li>O sistema deve exibir capacidade e recursos disponíveis</li>
  <li>O sistema deve reservar pelo mesmo fluxo das salas</li>
</ul>

**[↑ Voltar para US-004](#us-004)** | **Característica:** [C02 - Visualização e mapa de ocupação](#c02) | **Requisito:** [RF-07](/REQ-2025.2-T01-Softex/visao/levantamento-parcial#rf-07--visualizar-mapa-interativo-da-planta-)

## MVP — Produto Mínimo Viável

O MVP (Produto Mínimo Viável) do sistema de reservas da Softex foi definido com base nos requisitos funcionais considerados essenciais para validar a proposta de valor junto aos colaboradores e gestores da empresa. A seleção dos itens priorizou as funcionalidades **Must Have**, indispensáveis para o funcionamento básico do sistema, além de algumas **Should Have** que complementam a experiência do usuário sem comprometer a viabilidade técnica inicial.

O foco foi garantir que os colaboradores tenham uma jornada simples e funcional para visualizar a disponibilidade de salas e estações, realizar reservas e receber confirmações, enquanto os gestores e administradores possam monitorar a ocupação, gerenciar recursos e gerar relatórios básicos de forma segura e organizada. Dessa forma, o MVP permitirá validar rapidamente se a solução atende às expectativas de eficiência e usabilidade, possibilitando iterações futuras para evolução do produto.
